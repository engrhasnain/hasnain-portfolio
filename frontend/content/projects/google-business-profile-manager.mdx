## The problem

For a contractor, the Google Business Profile is often the first thing a new customer sees. The agency looks after many of them, and each one needs the right categories, services, hours, photos and review replies. Doing that by hand is slow, and a careless edit can do real damage to a listing. There is a quieter problem too: Google can accept a change and still not show it, so a successful API response is not the same as a correct listing.

## What I built

- **Listing sync and audit.** Each profile is pulled in, compared with the verified business data, and checked for NAP (name, address, phone) consistency.
- **A category recommender.** It fills at most 9 additional category slots and never pads them with weak matches just to fill the list.
- **Services, descriptions and photos.** Semantic matching maps the client's real services onto the listing, Claude drafts the business description, and the logo and cover photo are pushed from the same place.
- **Review-reply automation.** Claude drafts replies to new reviews, and they post on a delay that looks like a person answering, not a script.
- **Fleet runs.** Holiday hours go out across every listing in one run, and a mislink sweep finds clients connected to the wrong Google listing, for example an unverified listing when a verified one exists in a connected account.
- **A weekly policy check.** Google's published guidelines and API schema are checked against the console's rules every week, and the result is kept as a dated record. A change becomes a proposal, never an automatic update.
- **The console.** A React console with a health strip, a listing switcher, pending edits and a push bar, editors for categories, services and service area, AI review replies, photo slots, performance, sync and a full write log.

Every change starts from verified data, not from whatever is on the listing today. The server decides whether the edit is allowed, writes it through the Business Information API, then reads the listing back to confirm Google is really showing it. The Account Management and Performance APIs cover access and reporting, and the public Google Places API finds a client's listing before they have granted management access. Test mode and a confirm-before-write step let a person see exactly what will change first.

## Built to be trusted

- **Risk tiers enforced on the server.** A field with no tier gets no action at all, and an unverified listing blocks every push with a message saying why. The same check runs again just before the write.
- **Read-back that allows for slow changes.** The check after a write can be re-run, so a change Google is still processing is not logged as a false failure.
- **Careful review replies.** Replies post after a random delay that never lands on a round time. 1 and 2 star reviews are held for a person.
- **Fleet pushes that touch one thing.** Holiday-hours runs merge only specialHours, and a 200 response is never treated as proof.
- **Trust that is earned.** A 4-stage capability ladder removes human gates only after the system has proved itself consistent, and every write is logged in two places with the old value, the new value, who made it and the read-back result.
