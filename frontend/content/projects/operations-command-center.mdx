## The problem

An AI platform with voice calls, publishing, syncs and scheduled jobs can fail quietly. A webhook stops arriving, a sync falls behind, a job throws at night, and nobody notices until a client does. Most dashboards make this worse: a check that never ran looks green because nothing says otherwise. The agency needed one place that shows what is really running, and says so plainly when it does not know.

## What I built

- **A health check catalog.** 159 checks across 12 systems, from voice and publishing to leads and data integrity, each with its own alarm rule.
- **Live evaluators.** 117 distinct evaluators read the live systems, each on its own schedule, started by runners that wake every 1 and 2 minutes.
- **An event log people act on.** Each event can be approved or tuned and has its own thread. A Claude chat assistant works with the client's context, and events on the wall carry an "Ask AI" button.
- **A fleet view.** Live calls and integration runs across all client businesses, in one place.
- **The operations wall.** A NOC-style screen with views for systems, clients, calls and events, each with its own URL hash. It cycles every 20 seconds, takes arrow-key navigation and refreshes every 60 seconds, while the live calls poll keeps running in the background.
- **Honest status lights.** The sidebar "Online" light reads a real health endpoint instead of a fixed value.

Runners wake every 1 and 2 minutes and start only the evaluators that are due, a few at a time. Each one reads its system and stores a status, a value and the time it ran. Staleness is worked out when results are read, so an old green result turns amber on its own, without anyone touching it. Problems that need a person land in the event log. The wall cycles through systems, clients, calls and events, so a team member walking past sees the current state without clicking anything.

## Built to be trusted

- **No false greens.** A job or feed that never ran shows "Never", not a pass, and a result older than twice its schedule is served amber as stale.
- **Failures stay visible.** When an evaluator throws, the run is marked failed and the previous result stays in place until it goes stale.
- **One runner at a time.** A database advisory lock lets only one API instance run the evaluators, and each evaluator has a 60-second timeout.
- **People in the loop.** Events are approved or tuned by a person and discussed in their own thread.
