## The problem

A contractor marketing agency looks after a large number of WordPress sites, and the small requests never stop: new opening hours, a different photo, a hero that looks wrong on mobile, a missing FAQ. Each one means signing in to another site, finding the right Elementor widget and checking that nothing else moved. Security and SEO work is the same job repeated site by site. It is slow, and it is easy to miss a site.

## What I built

- **201 tools for one fleet.** An MCP server, spread across 45 modules, that gives Claude typed tools for every client WordPress site the agency runs.
- **Page-builder editing.** 11 Elementor tools list a page's structure, update elements in bulk, clone, insert and delete them, and flush CSS across sites. 7 more do the same for WPBakery, and 4 extract a site's design system and kit globals.
- **Content and settings.** 57 tools cover posts, pages, custom post types, options, media, code snippets and theme settings.
- **Visual QA.** 16 render tools take screenshots, read computed styles, measure the page and audit the hero section, with an autofix for common hero problems.
- **Email to website.** 22 tools turn a client's email into a queued change that is approved, executed and pushed to the site.
- **Fleet security.** 36 tools replace .htaccess files, quarantine suspicious files, audit admin users, apply hardening templates, sweep Wordfence settings across the fleet, scan wp-config and manage plugins. An async scan finds shared code snippets across sites, and an hourly guard catches stale cache minification.
- **Schema, SEO and migrations.** 26 tools keep a schema roster, set and verify schema in bulk, extract FAQs, remove inline JSON-LD, set SEO meta and move redirects. 4 more plan a blog migration, run it in batches, reconcile it and roll it back.

Claude connects over Streamable HTTP on a single /mcp endpoint and signs in with OAuth 2.1. When a client emails a request, it becomes a change in the queue with a confidence score and an SEO impact rating. Anything below 85% confidence, or with high SEO impact, goes back to the client to confirm. By default a change is approved automatically only at 95% confidence with low SEO impact, and each client can have its own overrides. Execution has two steps: a first call with confirm=false shows exactly what will change, then the real push runs. Writes go through the WordPress REST API with Application Passwords, or over SSH with WP-CLI when the API is not enough.

## Built to be trusted

- **An autofix that can say no.** The hero autofix refuses to run unless three checks pass, and a separate tool reverts it.
- **Migrations can be undone.** Every blog migration can be reconciled against the source and rolled back.
- **Every write says how to check it.** Each write tool returns how to read the result back, so Claude confirms a change instead of assuming it worked.
- **A guarded renderer.** The Playwright renderer blocks private IP ranges and the cloud metadata address, so a page URL cannot be used to reach internal services.
- **Logged and locked.** Middleware logs every request, including rejected sign-ins. Site credentials live in a Fernet-encrypted vault.
