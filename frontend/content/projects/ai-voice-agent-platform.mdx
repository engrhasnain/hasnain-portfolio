## The problem

The agency has to reach its client businesses by phone all the time: to confirm profile details, walk through a services list, book a callback, or get a yes before something goes live. Doing every call by hand does not scale. A voice bot that writes whatever it hears into a client's record is worse, because one misheard address spreads into listings and websites. The agency needed agents that hold a real call, and a person who still decides what changes.

## What I built

- **A function layer for live calls.** The agents can call 37 signed functions: 7 read the call context, 3 confirm who is calling, 5 save what was said, 6 edit the service area and services list, 9 run the profile approval call, 4 run content and project calls, and 3 book callbacks, hand off or queue a listing fix.
- **A 4-tier inbound gate.** Before the agent speaks, the caller gets the full agent, a limited agent that can only check authority and book a callback, a static message with no LLM, or a decline.
- **Callback and reconnect dialers.** Booked calls dial from BullMQ queues, and an approval call that has to stop is redialed within seconds and resumes at the next unconfirmed block.
- **Post-call reconciliation.** Captured answers become proposed changes, and OpenAI embeddings match each spoken field name to the right profile field.
- **A Retell control plane for Claude.** A Python MCP server gives Claude 101 Retell tools for campaigns, script edits and tests, live calls, knowledge bases, QA and alerts, and account and number admin.
- **Brand voice text to speech.** Five more tools speak text in each client's ElevenLabs voice, with word timing, cached renders and character caps.
- **A voice operations console.** An 11-tab React console covers calls, review, agent settings, prompts, functions, numbers and the gate, plus a calendar to schedule calls.

On an inbound call, the gate picks the agent before pickup. I designed it to fail toward the cheap, safe option: if the gate itself errors, the caller gets the static agent with no LLM. During the call, the agent opens with a short brief of past calls and open promises, fetches long lists one block at a time, and saves answers as it goes. A booked callback returns a line to read word for word. When the call ends, Retell AI sends signed webhooks, and reconciliation compares the answers with what is on file. The differences reach review as proposed changes, not edits.

## Built to be trusted

- **Signed, idempotent webhooks.** Webhooks and function calls are checked with HMAC-SHA256 and a five-minute replay window, and each event is stored first so a repeat is skipped.
- **Claims are checked in code.** If the agent logs a call as approved but the approval function never recorded it, the outcome is downgraded and the team is alerted.
- **Identity data stays with people.** Name, address and phone changes go to a listing queue, weak answers go to review, and nothing from reconciliation applies until a person accepts it.
- **Two-step confirm for Claude.** Tools that spend money or change config return a preview and a one-time token tied to the exact arguments, while stopping a live call needs no confirm.
- **Guarded promises.** A number is verified only when the owner confirms it on a call, and any promise to access a client's customer data is flagged for compliance review.
