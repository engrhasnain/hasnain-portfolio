## The problem

Every contractor site should look and sound like the business behind it. In practice the brand lives in a dozen places: an emailed logo, colours copied from an old site, a theme that claims one page builder and uses another. AI pages built from that repeat every mistake: weak contrast, the wrong blue, a blurry logo, generic copy.

## What I built

- **Versioned brand guides.** Each site has a guide with design tokens (colours, type, spacing, radius, shadows, motion, breakpoints), component patterns, voice and imagery rules. Every save is a new version with a semantic version bump, a per-field diff and a change log entry.
- **Quality gates.** Colours must be valid hex, text must meet WCAG AA contrast (4.5:1 for normal text, 3:1 for large text and buttons), required tokens and components must exist, and colour token names can never be removed or renamed.
- **Logo handling.** SVGs are parsed with entities and network access off, then cleaned of scripts, event handlers and editor clutter, a missing viewBox is built, and files with embedded rasters or live text are rejected. Flat-colour raster logos can be traced to SVG with vtracer, and a plain pixel check removes backgrounds but refuses gradients and soft edges.
- **Page-builder detection.** A public, read-only check finds the builder a live site really uses (Elementor, WPBakery, Divi, Beaver Builder, Bricks, Oxygen or Avada) without trusting the WordPress generator tag, and tells real Elementor kit colours from factory defaults.
- **Voice profiles.** Claude reads a call transcript of at least 500 words and records tone, formality, reading level, signature phrases and phrases to avoid. The content voice stays a draft until a person approves it.
- **Creative briefs.** Claude Haiku extracts the facts, then Claude Sonnet writes the brief: ideal customer, positioning, voice and what content should lead with.
- **Pages from brand tokens.** Claude Sonnet builds pages from the approved guide, the voice profile and verified business data. The portal's brand-guide editor has a live contrast report, component previews, logo and voice panels, and a diff before saving.

A guide read from a live site is only a proposal. Confirming it needs a written note from a person, and approval is refused while any role on that site is open in the review queue. Generators read the approved version only and refuse to run when a site has none. Each page passes checks for forbidden phrases, structure, NAP details, schema, image zones and word floors, plus site-wide checks for keyword cannibalisation, broken links and other clients' details. Previews stay noindex. Once a week, anything that moved on an approved site becomes a review item, never an edit. Claude does the same work through MCP tools.

## Built to be trusted

- **Gates that hold.** In the portal a gate error blocks the save. Through Claude the save keeps its findings and the errors block approval.
- **No silent overwrites.** Old versions stay, rejected proposals are kept so they are not re-proposed, and a replaced logo can be restored.
- **A person decides on logos.** A vector trace becomes the primary logo only when someone approves it. Background removal shows a preview and keeps the original.
- **Dry run first.** Token writes to a site's builder kit start as a dry run, and a live write needs a backup and before and after screenshots.
