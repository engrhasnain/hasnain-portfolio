## The problem

Onboarding and sales calls hold most of what the agency needs to know about a new client: services, service areas, hours, the address. Typing it up after each call is slow and patchy. An AI summary is not safe either, because a model can invent a detail or put the rep's words in the client's mouth. Calls also carry risk: clients read card numbers and passwords out loud, and those must never reach storage.

## What I built

- **A live transcript that redacts as it goes.** A Zoom RTMS consumer stores each line with its speaker and time after card numbers and passwords are redacted. Digits read out one group at a time are held until the reading ends, so no part of a card is ever stored.
- **Streaming only where there is consent.** The stream connects only for the onboarding part of the call, once the rep starts it. The sales part and internal meetings are never streamed.
- **A live coverage checker.** A map gives each of 150 profile fields exactly one owner. During the call, a checker reads the new lines and shows the rep which fields are still open.
- **Answers checked after the call.** The model proposes a value for each field with the client's own quoted words. Code then checks each quote, its timestamp and the speaker, and verifies addresses with a geocoder.
- **Sales call review.** A deal review reads the redacted sales call transcripts through one forced tool call. Quotes that do not match the transcript word for word are dropped, the score is computed in code from its parts, and the prompt is checked for card numbers before it is sent.
- **PCI redaction on recordings.** Stored recording transcripts are scanned with a Luhn check plus nearby context words for card numbers, security codes and expiry dates, and each redaction is logged. Recordings are matched to clients through aliases, with a review queue for ambiguous matches.
- **Meeting automation.** A Zoom room is created when a charge is approved. Recurring schedules use RRULE with timezone conversion, and events go to Google Calendar through OAuth.

The live checker is guidance for the rep and writes nothing. After the call, the recording is the only source of answers. The model's output is a proposal: a field closes only when the client's own answer is on the recording, and a single "yes" to a bundle of the rep's claims answers nothing. When every required field passes, the answers are written and read back. If any are missing, nothing is written and a follow-up call is prepared with only the open questions.

## Built to be trusted

- **Versioned prompts.** Prompts are editable at runtime, and every answer is stamped with the prompt version that produced it.
- **Cost caps per call.** The live checker is throttled, with caps on checks and cost for each call, and every model read is logged as a cost event.
- **Signed, idempotent webhooks.** Zoom webhooks are signature-verified and carry an idempotency key, so a repeat delivery is never processed twice.
- **Protected credentials.** Google refresh tokens are encrypted with AES-256-GCM, and the OAuth state is checked to stop CSRF.
- **Approval before commit.** The call and job intake tools Claude uses hold each item for approval before it is committed.
